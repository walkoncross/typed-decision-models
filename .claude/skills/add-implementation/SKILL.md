# 收录一篇新的实现调研文档

本仓库 `typed-decision-models` 按 `docs/<实现名>/` 收录各实现（RYOTIDE / Jeff / Open-Jev / Quyet）的逐环节走查。这个 skill 只做**放置、登记、加列、校验**四步。

## 边界：本 skill 不做什么

- **不写正文**。走查的价值在于「每个数字都能追溯回源码文件名与行号」，这必须来自读上游代码，套模板生成出来的东西没有收录价值。正文由人或 agent 先行写好，本 skill 只把它放到位。
- **不推断技术结论**。`comparison.md` 里需要判断的格子（某实现的「顺序偏置」是「不存在该变量」还是「未涉及」）必须从新正文里读出来，不能猜。正文没覆盖的维度就写 `未涉及（其 §X）`。
- **不复述收录约定**。约定只有一份，在 `README.md` 的「收录约定」一节。本 skill 引用它，不抄它——抄了就会出现两处不一致。动作前先读那一节。

## 需要先问清楚的输入

1. **实现名**（用作目录名，如 `laya`）；
2. **上游代码库 URL**（写进文首，须与 README 副本来源表里的 URL 一致）；
3. **正文来源**：源文件路径，或已写好的内容。若源文件名是 `implementation.md` 这类泛名，按约定改名为主题名（默认 `typed-decision-model.md`）；
4. **是「移动」还是「复制」**：默认只在文首补链接、**保留原件**；只有用户明确说移动时才归档原件。

## 步骤 1：建档

```bash
mkdir -p docs/<实现名>
cp <源文件> docs/<实现名>/<主题名>.md
```

若用户说的是「移动」：原件用 `mv` 归档到 `~/claude-temp/<实现名>__<原路径扁平化>.md`，**不要用 `rm`**。

然后改文首与交叉引用（**这是本步骤唯一需要判断的地方**）：

- 在 `# 标题` 之下、`> 对应 README ...` 之上插入一行：`> 代码库：<URL>`；
- 给已有的「本文按 `src/xxx/` 的实际代码逐环节说明这句话的实现方式。」这句补上后缀：
  `；文中出现的文件名与行号（`a.py:1`、`b.py:2` 等）均相对该仓库根目录。`
- 把指向 RYOTIDE 那篇的路径（含绝对路径）统一改为库内相对路径 `../ryotide/typed-decision-model.md`。

正文其余部分**逐字不动**——副本要保持与上游可按路径比对。

## 步骤 2：登记 README

在 `README.md` 的「目录」表加一行：`| <实现名> | [`docs/<实现名>/<主题名>.md`](docs/<实现名>/<主题名>.md) | <两三句概括：节数、关键环节、是否含实例走查> |`

在「关于各篇文档」的副本来源表加一行，写明上游代码库、副本来源与是否改名。若该实现引入了新的口径差异（如不同 ECE 分箱），同时在 `comparison.md` §5 补一条。

## 步骤 3：给 comparison.md 加列

`docs/comparison.md` 是四路总表，新增一路要动**九张表**，逐张确认，不要只改主表。

注意区分**加列**还是**加行**——表中「实现」是列还是行并不统一，只有 §1 和 §3 是加列，其余全是加行：

**加列（实现为列）**

- [ ] §1 主对照表（12 个维度）
- [ ] §3 四条不变量跨篇落位表（判据不足的实现要写「概念不适用」并给出改写后的等价命题，**不要硬套**）

**加行（实现为行）**

- [ ] 开头「收录的四条路线」索引表
- [ ] §2「谁在改发布数值」表
- [ ] §2「温度的具体值 / 来自哪」表
- [ ] §4.1 `enable_thinking=False` 三种接法
- [ ] §4.2 填充方向（无此设计的实现要显式说明「不适用」）
- [ ] §4.3 混合架构 cache 坑（无此坑就写「无此坑：<原因>」）
- [ ] §4.5「算得出来 ≠ 接进来了」（没有这类观察就写「无」）

**非表格，但要改**

- [ ] §4.4（散文）—— 把新实现归入「读出来的」或「训出来的」置信度那一类
- [ ] §3 最后一行—— 若该实现提出了 RYOTIDE 四条之外的不变量，补上
- [ ] §5 —— 若该实现引入了新的口径差异（如不同的 ECE 分箱），补一条

**表格里的每个格子都要有出处**，格式与既有行 / 列一致（带其 §X 节号）。判据不足的格子写 `未涉及（其 §X）`，不要留空、不要猜。

## 步骤 4：校验

```bash
.claude/skills/add-implementation/check.sh
```

九项全过才算完成：编码、目录结构、文件名、文首两行、无绝对路径、相对链接可解析、README 已登记、comparison.md 已覆盖、代码库地址两处一致。

任何 FAIL 都要修到通过为止——尤其第 5 项（本机绝对路径）和第 7、8 项（登记与覆盖），它们最容易漏，而且是**只有机械检查才抓得到**的一类错误。

## 收尾

按仓库的提交规范提交，`docs` 类型，说明里写清：新增哪个实现、文件名是否改过、README 与 comparison.md 各自动了什么。
